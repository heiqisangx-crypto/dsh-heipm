# quest-list（任务清单）

> **触发**：用户消息出现「新需求」时。

## 落地文档前需要做什么?
- **动手前** 抽出高层需求，记录为编号段落标题。拆分为具体、可执行的子任务。用明确的状态标记维护每个子任务。
- **验收后** 将记录的子任务合并为一段话，让用户看懂这一节具体完成了什么。用一句简短的话描述，不要长篇大论、不要写用户验证完成这种废话，能到这一步用户肯定是验收完成的。

## 标记含义
| 标记 | 含义 |
|------|------|
| `[ ]` | 未完成 / Not started |
| `[O]` | 待验证 / Awaiting verification |
| `[√]` | 已完成 / Completed |

## 面板
「项目管理 → 任务清单」分区会读取这份文件：有子项的条目只显示「未完成/已完成」并支持展开收起，没有子项的条目带勾选框，点一下按「未完成 → 待验收 → 已完成 → 未完成」循环并直接写回文件。

## 格式
用户说：`我需要你给登录页加验证码`
响应（追加到 `.dsh/dsh-heipm/任务清单.md`）：

```markdown
[ ] 五、登录页验证码
	[ ] 设计验证码生成接口
	[ ] 前端验证码组件
	[ ] 校验逻辑与错误提示
	[ ] 单元测试
```

用户说：`验收完成`
响应（修改整个一节任务，并写回）：
```markdown
[√] 五、给登录页验证码：设计了验证码生成接口、前端验证码组件、校验逻辑与错误提示
```
