# quest-list（任务清单）

> **触发**：用户消息出现「新需求」时。

## 落地文档前需要做什么?
- **动手前** 抽出高层需求，记录为编号段落标题。拆分为具体、可执行的子任务。用明确的状态标记维护每个子任务。

## 标记含义
| 标记 | 含义 |
|------|------|
| `[ ]` | 未完成 / Not started |
| `[O]` | 已动手、**未验证** / Awaiting verification |
| `[√]` | 已验证且有证据 / Completed |

## 证据门槛
- `[O]` 已经写进文档，就等于声明「代码写完了但还没证明」。它必须带证据：命令 + 输出、`文件:行号`、或测试条数。
- 没有证据的项**不许**改成 `[√]`；点面板也一样，先补证据再点。
- 证据写在同一行的 `｜ 证据：` 之后，**不要另起子行** —— 面板会把子行当成子任务。
- 「没报错」「看着对」不是证据。

## 面板
「项目管理 → 任务清单」分区会读取这份文件：有子项的条目只显示「未完成/已完成」并支持展开收起，没有子项的条目带勾选框，点一下按「未完成 → 待验收 → 已完成 → 未完成」循环并直接写回文件。

## 格式
用户说：`我需要你给登录页加验证码`
响应（追加到 `.dsh/dsh-heipm/任务清单.md`）：

```markdown
[ ] 五、登录页验证码
	[ ] 设计验证码生成接口
	[ ] 前端验证码组件
	[ ] 校验逻辑与错误提示
	[ ] 单元测试
```
干活中途（写完但没验）：
```markdown
[O] 五、登录页验证码
	[√] 设计验证码生成接口 ｜ 证据：src/api/captcha.ts:24
	[√] 前端验证码组件 ｜ 证据：npm run build → ok
	[O] 校验逻辑与错误提示 ｜ 证据：npm test test/login.test.mjs → 8 passed（删掉校验分支后转红）
	[ ] 单元测试
```
