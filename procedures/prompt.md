# 经验流程（procedures）

各工作区 `.dsh/dsh-heipm/procedures/` 存**踩过的坑与解法**，不常驻注入，按需读。

- **动手前 · 两步，别只做第二步**：
  - **① 冷启动**：任务里出现 **URL / 仓库链接 / 「装不装、值不值得装」** 这类动作时，**还没撞上任何现象就先搜一次**（按任务里的名词），**命中就直接打开第一张**；**第一次失败后必须回头查一次卡库**，再动手修。
  - **② 撞上现象/同一现象/同一命令失败第二次失败**（网页抓不到正文 / 改了不生效 / 报错原文 / 命令无输出 / Permission denied / 资源查不到 / JSON 解析为空）：
    `grep -il "锚点.*<任务词>" .dsh/dsh-heipm/procedures/*.md` —— **只搜锚点行**，一次一张；没命中再退回全文 `grep -il "<任务词>" .dsh/dsh-heipm/procedures/*.md`
    （Windows 无 grep：`Select-String -Path procedures\*.md -Pattern "锚点.*<任务词>"`）。
    ★ 搜的是**任务词**，不是「触发」这个字面词 —— 搜它只会把每张卡的触发行打出来，等于没筛。
    ★ **别用 glob / 列目录挑卡** —— 列名看不到锚点。

- **踩到坑的当时 —— 最重要的一条**：只要这次不是「照着卡做就顺了」，而是**又试错了几轮**，就立刻往 `procedures/_inbox.md` 记一行（现象 + 一句话解法）。
  **别等收尾** —— 收尾要靠回忆，回忆不可靠；当下记，不会忘。**记一行也算数，别因为没想清楚就不写。**
  **记 inbox 是记笔记、不是"动手改文件"** —— 就算被要求「只读 / 先别动手」，也照记不误；
  **但任务若明令「只读」**（例如"不要创建任何文件"），就把那一行写在**回复末尾**并注明「待记 inbox」，由上层或下次会话补写 —— 既不违令，也不丢痕。

- **收尾时（是检查，不是回忆）**：在说出「完成 / 搞定了 / 修好了」之前，看一眼 `_inbox.md`：
  - 在记录正式卡之前，必须看一下 `CLASSIFY.md`进行判断
  - 有够格的（复发的 / 代价大的）→ 照 `card-template.md` 整理成正式卡，删掉那行 inbox。**文件名就是索引**：写成 `分类-现象`，现象词用「任务里会出现的说法」。
  - 只是小意外 → 留在 inbox，下次开工再整理。

- **一张卡写四条**：触发条件 / 首选姿势（可直接抄）/ 反面清单（试过不通的）/ 验证方式（怎么确认真成了）。
  「验证方式」必须写**两截**：哪一步能让它**变红**、哪一步能证明它**变绿**。只写「跑通了 / 没报错」的卡不许入档。

- **不扫描、不复制**：不做启动式全库扫描；检索一律**定向** —— 拿任务里的现象词去搜，命中几张读几张。卡片正文不进本文件，本文件与 `INDEX.template.md` 只放指针。

- **工具（procedures-tools）· 按需才用，只有一份**：脚本随插件分发（`dsh-heipm` 包内 `templates/tools/`），**不要再往任何项目里复制** —— 它们都支持 `--dir` / `--procedures` / `--workspace` / `--sessions` 指向任意目录或工作区。**不要预读 README、不要主动运行**；只有用户明确要求做其中一件事（挖历史会话 / 验证触发 / 静态体检 / 使用评审）时，才按说明带参数运行。**路径别自己猜**：直接用斜杠命令 `proc-audit` / `proc-review` / `proc-scan` / `proc-probe`，它们会给出带绝对路径的现成命令。
- **没踩过的原则只进 inbox**：CRAP < 10、重复度 ≥ 0.8、变异测试这类**度量门槛**，在没有真实工具落地之前不写进 AGENTS、也不成卡，只在 `_inbox.md` 留一行等它复发。规则一旦先于体验存在，就只是口号。
